# Online appointment booking for patients design

Date: 2026-11-02 · Status: draft for review
Ticket: 59 · Intent: docs/intents/online-appointment-booking.md (ThanhTruong, role TBD)

## Goal
Patients cannot book an appointment online. A patient chooses a doctor, picks one of that doctor's free time slots and books it, and the system never allows two appointments in the same slot for the same doctor.

## Scope
- In: doctors and their bookable slots, listing free slots, booking a slot, a double-booking guard, and a reception admin screen to maintain doctors' weekly schedules and days off. Extends `clinic-app/` (FastAPI + SQLModel + SQLite, React). It runs inside the existing clinic app on 127.0.0.1.
- Out (not now): login or accounts for patients, cancel and reschedule, email or SMS confirmations and reminders, payments, links to the walk-in queue, reception-side booking screens, linking an appointment to a patient record (reception matches by phone later), and public exposure of the booking page (sync to the clinic app, hosting, auth and rate limiting; deferred, see ADR 0001).

## Requirements
- R1. The patient can list the doctors available for booking.
- R2. The patient can list one doctor's free slots for a given date; booked slots are not returned.
- R3. The patient can book a free slot by sending the doctor, the slot and the patient's name and phone; the response returns the appointment. Booking is as a guest, with no account. (Decided by ThanhTruong (lead, as product owner) on 2026-11-03.)
- R4. A slot that is already booked cannot be booked again (409), including when two bookings for the same slot arrive at the same time; exactly one succeeds.
- R5. A slot in the past, or one that does not exist for that doctor, cannot be booked (404 or 422, see Errors).
- R6. Empty or whitespace-only name or phone is rejected (422); text fields are trimmed, like the rest of the app.
- R7. All timestamps and "now" come from `clock.py`, never `datetime.now()`. Slots are stored as naive local clinic time (`Asia/Ho_Chi_Minh`), like `visited_at` (`clinic-app/backend/app/clock.py:4-13`, `clinic-app/backend/app/models.py:118`). The booking page shows dates in clinic time, as `RevenuePage.tsx` does.
- R8. Appointments are never hard-deleted. (Assumption: keeps room for cancel and reschedule later.)
- R9. The existing clinic app stays bound to 127.0.0.1. This ticket adds no public access, auth, rate limiting, hosting or sync; those are deferred (`docs/adr/0001-public-booking-service-for-online-appointments.md`). Tests use fake data only.
- R10. Reception can add a doctor and set a doctor's weekly schedule and days off in an admin screen. Default template: Mon-Fri 08:00-17:00, 30-minute slots. (Decided by ThanhTruong (lead, as product owner) on 2026-11-03.)

## Design
### Data model
**doctors**: `id`, `full_name` (required), `is_active` (default true).
**slots**: `id`, `doctor_id` (FK), `starts_at`, `ends_at`. Unique together on (`doctor_id`, `starts_at`). Slots are generated by the system from a weekly template per doctor: **doctor_schedules** (`doctor_id`, `weekday`, `start_time`, `end_time`, `slot_minutes`) and **doctor_days_off** (`doctor_id`, `date`). Default template Mon-Fri 08:00-17:00 with 30-minute slots, maintained by reception in an admin screen (R10). How slots are generated (ahead of time or when a date is listed) is decided in the plan. (Decided by ThanhTruong (lead, as product owner) on 2026-11-03.)
**appointments**: `id`, `slot_id` (FK, unique), `patient_name`, `patient_phone`, `created_at`.
- Double booking is blocked in the database: the unique `slot_id` on `appointments` rejects a second booking, and the router maps that error to 409.
- A booking keeps a free-text name and phone and has no link to a `patients` row; reception matches it by phone later, in the local app. (Decided by ThanhTruong (lead, as product owner) on 2026-11-03.)
### Screens
1. **Choose doctor**: list of active doctors.
2. **Choose slot**: date picker and the doctor's free slots for that date.
3. **Confirm booking**: name and phone form, then a confirmation with the appointment details.
4. **Doctor schedules (reception)**: add a doctor, edit the weekly schedule, add or remove days off.
### API
| Method | Path | Purpose |
|---|---|---|
| GET | `/doctors` | doctors available for booking |
| GET | `/doctors/{id}/slots?date=` | free slots of a doctor on a date |
| POST | `/appointments` | book `{slot_id, patient_name, patient_phone}` |
| POST | `/doctors` | add a doctor (reception) |
| PUT | `/doctors/{id}/schedule` | set the weekly schedule (reception) |
| POST, DELETE | `/doctors/{id}/days-off` | add or remove a day off (reception) |
### Errors
- Required field empty or whitespace -> 422.
- Unknown doctor or slot -> 404.
- Slot already booked -> 409.
- Slot start is in the past -> 422.
- Booking and its uniqueness check happen in one transaction: all or nothing.
### Layout
```
clinic-app/
  backend/app/{models.py, routers/{doctors,appointments}.py}
  backend/tests/{test_appointments.py, test_doctor_schedules.py}
  frontend/src/{pages/{BookingPage,DoctorSchedulesPage}.tsx, __tests__/}
```

## Testing
- Test-first, like `test_visits.py`: pytest with in-memory SQLite. Cover free-slot listing, successful booking, booked slot hidden and rejected (409), concurrent double booking (one wins), past slot, unknown doctor or slot, blank fields, clock patched.
- Schedules: slots follow the weekly template, days off remove slots, a day off does not remove an already booked appointment's record (R8).
- Frontend: vitest for the slot list, the booking form and the schedules screen.
- Fake data only.

## Data safety
- Patient name and phone are personal data: do not log request bodies, and never commit `*.db`.
- The clinic app binds to 127.0.0.1 and has no login. This ticket does not expose it: public access (separate booking service, auth, rate limits, hosting, sync) is deferred under ADR 0001 and needs its own ticket and privacy rules before any port is published.
- No real patient data in any AI tool or in tests.
